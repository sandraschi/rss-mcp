# rss-mcp user guide



This guide shows how a human uses the local RSS reader day to day.



## Lesson 1: RSS subscription lifecycle with ETag and Last-Modified conditional GET

As a user I want rss subscription lifecycle with etag and last-modified conditional get. I open the Feeds page, add a URL, run refresh, open the Reader three pane view, pick an item, click extract for clean text, star what matters, mark read when done. Section 1 covers RSS subscription lifecycle with ETag and Last-Modified conditional GET. Agents subscribe with feeds_ops subscribe, list with list_feeds, refresh with refresh_feed or refresh_all, read items with fetch_items and get_item, mark state with mark_read and mark_star, move collections with opml_import and opml_export, check liveness with feed_health. Extraction uses readability_ops extract with cache, get_cached for repeats, clear_cache for invalidation, list_extractors for engine info. Reading uses reader_ops inbox for unread, starred for saved, search_text for full text, search_semantic for vectors with fallback, stats for counts, trigger_sweep and sweep_status for background refresh. All results are dialogic dicts with success and message plus domain fields. The Prefab card show_reader_prefab_card renders counts in chat with a text fallback. Storage is local SQLite WAL at RSS_MCP_DB or data rss.sqlite3. Ports are backend 11974 and frontend 11975. No wrappee and no account so onboarding is not applicable.
